# Fixly CRM — Project Overview

## Що це за проєкт

Fixly CRM — SaaS CRM-система для малого сервісного бізнесу (салони краси,
барбершопи, ремонтні майстерні, приватні студії тощо), яка дозволяє керувати
клієнтами, послугами, працівниками та записами в одному місці.

Кожен бізнес реєструється в системі окремо і працює у своєму ізольованому
просторі даних (мультитенантність через `businessId`). Власник бізнесу додає
працівників, клієнтів, послуги і керує записами через календар.

## Для кого

**Основний користувач:** власник малого бізнесу / адміністратор.

**Другорядний користувач:** працівник (employee), який бачить і веде свої
записи та клієнтів у межах бізнесу, до якого належить.

## Ключова ідея мультитенантності

Це не CRM для одного бізнесу — це платформа, де кожен бізнес має власний
ізольований набір даних:

```
Business A (businessId = 1)          Business B (businessId = 2)
   ├── Users (admin, employees)         ├── Users
   ├── Customers                        ├── Customers
   ├── Services                         ├── Services
   └── Appointments                     └── Appointments
```

Користувач Business A **ніколи** не повинен мати доступ до даних Business B.
Ця ізоляція перевіряється на рівні кожного запиту до бази (middleware +
фільтрація по `businessId`) і є однією з найважливіших частин архітектури.

## Основні можливості (MVP)

- 🔐 **Авторизація** — реєстрація бізнесу, логін/логаут, ролі `admin` /
  `employee`, захищені сторінки.
- 📊 **Dashboard** — кількість клієнтів, записи на сьогодні/найближчим часом,
  дохід, коротка статистика.
- 👥 **Customers** — список, пошук, профіль, CRUD, історія записів клієнта.
- 🛠 **Services** — назва, опис, ціна, тривалість, CRUD.
- 📅 **Appointments** — клієнт + послуга + працівник + дата/час + статус
  (`scheduled`, `completed`, `cancelled`), перегляд у вигляді списку/календаря.
- 👤 **Employees** — додавання, перегляд, призначення записів.
- ⚙️ **Settings** — профіль користувача, дані бізнесу.

## Що свідомо залишено на потім (щоб не розрости у монстра)

- Публічна сторінка бронювання для клієнтів бізнесу (без логіну).
- Автоматична перевірка конфліктів розкладу і робочі години/вихідні.
- Email/SMS нагадування про записи.
- Тарифні плани / підписка (subscription plans).
- Docker + повноцінний деплой.

Ці пункти важливі для "дорослого" продукту, але додаються **після** того, як
працює базовий MVP: Auth → Business → Customers → Services → Appointments →
Dashboard.

## Технічний стек

**Frontend:** React, JavaScript, React Router, Redux Toolkit + RTK Query,
Tailwind CSS.

**Backend:** Node.js, Express, JavaScript, Prisma ORM, PostgreSQL.

**Інше:** Git/GitHub, REST API, JWT/Cookies для авторизації, Swagger для
документації API, Docker — ближче до завершення проєкту.

## Чому PostgreSQL + Prisma, а не MongoDB

Дані в CRM сильно реляційні: `Customer → Appointment → Service + Employee`,
і все прив'язане до `Business`. Такі зв'язки природно виражаються через
foreign keys у SQL, а Prisma дає типізовану, наочну схему і зручні міграції.
Це також простіше для дебагу консистентності (наприклад, що робити з
Appointment, якщо видалили Service, на який він посилається).
